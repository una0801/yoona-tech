- **진법** → 같은 수를 몇 개의 기호로 묶어 표현하는 약속 (10진·2진·16진)
- 컴퓨터 내부는 0/1 두 기호뿐 → 음수·소수·문자 모두 2진 패턴으로 약속해 저장
- 2의 보수·IEEE754·UTF-8 → "비트 묶음을 무엇으로 읽을지" 정한 규칙

## 시계 거꾸로 돌리기로 보는 음수

- 12시 시계에서 -3시간 = +9시간 → 같은 자리 도착
- 고정된 자릿수(시계 12칸·정수 비트 8칸)에서 빼기를 더하기로 바꾸는 발상
- 이 발상이 **2의 보수** → 빼기 회로 없이 덧셈기 하나로 음수 처리

<KeyPoint title="이 페이지에서 가져갈 것">
같은 비트 패턴도 "어떤 규칙으로 읽느냐"에 따라 값이 달라짐 ·
부호 정수(2의 보수)·실수(IEEE754)·문자(UTF-8)는 모두 약속 ·
약속을 벗어나면 오버플로·오차·깨진 문자 발생
</KeyPoint>

## 진법 변환표

- 각 진법은 자리당 사용하는 기호 개수(밑)가 다름 · 2진 2개·8진 8개·16진 16개
- 16진 1자리 = 2진 4자리 → 비트를 사람이 읽기 쉽게 묶는 용도

| 10진 | 2진 (0b) | 8진 (0o) | 16진 (0x) |
| --- | --- | --- | --- |
| 0 | 0000 | 0 | 0 |
| 5 | 0101 | 5 | 5 |
| 10 | 1010 | 12 | A |
| 15 | 1111 | 17 | F |
| 16 | 1 0000 | 20 | 10 |
| 255 | 1111 1111 | 377 | FF |

```python
n = 255
print(bin(n))   # 0b11111111
print(oct(n))   # 0o377
print(hex(n))   # 0xff
print(int("ff", 16), int("0b1010", 2))  # 255 10
print(f"{255:08b} {255:#x}")            # 11111111 0xff
# 결과: 같은 255가 진법별로 다른 표기 · 값은 동일
```

## 2의 보수 — 음수 표현

- 양수 비트를 모두 뒤집고(NOT) +1 → 그 수의 음수
- 8비트 기준 표현 범위 -128 ~ 127 · 최상위 비트(MSB)가 부호
- 시계처럼 한 바퀴 도는 모듈러 → 덧셈기 하나로 뺄셈 처리

| 10진 | 8비트 2의 보수 | 설명 |
| --- | --- | --- |
| 5 | 0000 0101 | 양수 그대로 |
| -5 | 1111 1011 | 5 뒤집고 +1 |
| -1 | 1111 1111 | 모든 비트 1 |
| -128 | 1000 0000 | 8비트 최솟값 |
| 127 | 0111 1111 | 8비트 최댓값 |

```python
def to_twos(x, bits=8):
    return x & ((1 << bits) - 1)      # 음수도 비트 패턴으로

print(format(to_twos(-5), "08b"))     # 11111011
print(format(to_twos(-1), "08b"))     # 11111111
# 검산: 5 + (-5) = 0000 0101 + 1111 1011 = 1 0000 0000 → 8비트 넘침 버려 0
print((5 + to_twos(-5)) & 0xFF)       # 0
# 결과: 음수 = 보수 + 자릿수 넘침을 버려 자연스럽게 0
```

## IEEE754 부동소수점 — 과학적 표기법

- 소수를 `부호 × 가수 × 2^지수` 꼴로 저장 → 과학적 표기법 `1.23 × 10³`의 2진 버전
- 64비트 double = 부호 1 + 지수 11 + 가수 52 비트
- 2진 분수로 정확히 못 쓰는 값(0.1·0.2)은 근사 저장 → 미세 오차

<Layers>
<Layer title="Sign 부호 1비트" sub="0 양수 · 1 음수" color="rose">
전체 값의 부호만 결정
</Layer>
<Layer title="Exponent 지수 11비트" sub="2의 몇 제곱 (bias 1023)" color="amber">
소수점을 어디로 옮길지 → 크기(스케일) 담당
</Layer>
<Layer title="Mantissa 가수 52비트" sub="유효숫자 (1.xxxx 형태)" color="sky">
실제 정밀도 담당 · 비트 부족하면 근사
</Layer>
</Layers>

```python
print(0.1 + 0.2)              # 0.30000000000000004  ← 오차
print(0.1 + 0.2 == 0.3)      # False
print(format(0.1, ".20f"))   # 0.10000000000000000555...
print(round(0.1 + 0.2, 10) == 0.3)  # True  반올림 비교

from decimal import Decimal
print(Decimal("0.1") + Decimal("0.2"))  # 0.3  정확 (10진 저장)
# 결과: 0.1은 2진 무한소수 → double로 못 담아 근사 · 돈 계산은 Decimal
```

<Note type="danger" title="부동소수점 실무 주의">
- 금액·환율 등 정확한 값 → `Decimal` 또는 정수(센트 단위) 사용
- 부동소수 == 비교 금지 → `math.isclose(a, b)` 또는 허용 오차 비교
- 큰 정수도 float로 변환 시 정밀도 손실 → ID·카운트는 int 유지
</Note>

## 문자 인코딩 — ASCII · 유니코드 · UTF-8

- 문자도 결국 숫자 → "어떤 문자에 어떤 번호" 약속이 인코딩
- **ASCII** 0~127 영문·기호 1바이트 · **유니코드** 전 세계 문자에 번호(코드포인트) 부여
- **UTF-8** 코드포인트를 1~4바이트 가변 길이 바이트로 변환 (영문 1·한글 3)

```mermaid
flowchart LR
  A["문자 '가'<br/>유니코드 U+AC00"] -->|UTF-8 인코딩| B["바이트 3개<br/>EA B0 80"]
  B -->|디코딩| A
```

```python
print(ord("A"), ord("가"))        # 65 44032
print(hex(ord("가")))             # 0xac00  유니코드 코드포인트
print("가".encode("utf-8"))       # b'\xea\xb0\x80'  바이트 3개
print(len("가".encode("utf-8")))  # 3   한글은 UTF-8에서 3바이트
print(len("A".encode("utf-8")))   # 1   영문은 1바이트
# 결과: 같은 '가'도 코드포인트(논리 번호)와 바이트(저장 형태)가 다름
```

## 오버플로 — 자릿수 넘침

- 고정 비트 정수는 표현 범위 한계 → 최댓값 +1 하면 최솟값으로 회전(wrap)
- 시계가 12 다음 1로 돌아가듯 비트도 한 바퀴 돎
- 파이썬 int는 무한 정밀도라 안전 · C/Java/DB·고정 비트 환경은 주의

<Compare>
<CompareCol title="고정 비트 (C·Java int32)" subtitle="범위 초과 시 회전" color="amber">
- 최댓값 2147483647 + 1 → -2147483648
- 오버플로 자동 wrap · 버그 원인
- 카운터·해시·곱셈 누적 시 위험
</CompareCol>
<CompareCol title="파이썬 int" subtitle="무한 정밀도" color="green">
- 자릿수 자동 확장 · 오버플로 없음
- `2**1000`도 그대로 계산
- 단 DB·외부 시스템 연동 시 범위 점검 필요
</CompareCol>
</Compare>

```python
INT32_MAX = 2**31 - 1
print(INT32_MAX)                  # 2147483647
val = (INT32_MAX + 1) & 0xFFFFFFFF
print(val)                        # 2147483648  (부호 무시 시)
# 32비트 부호 정수로 해석하면 -2147483648 로 회전
signed = val - 2**32 if val >= 2**31 else val
print(signed)                     # -2147483648
print(2**1000 > 0)                # True  파이썬은 오버플로 없음
# 결과: 고정 비트는 wrap · 파이썬은 무한 확장
```

<Note type="warning" title="시스템 경계에서의 정수">
- DB 컬럼 `INT`(4바이트)·`BIGINT`(8바이트) 범위 확인 후 저장
- 외부 API·C 연동 시 64비트 초과 ID는 문자열로 전달 권장
- 타임스탬프·곱셈 누적값 → BIGINT 또는 명시적 범위 검증
</Note>
