## 개념
- kubernetes에서 **컨테이너를 생성, 실행, 관리, 삭제하는 실제 실행 엔진**

| 항목  | 설명                                     |
| --- | -------------------------------------- |
| 정의  | 컨테이너 생성/실행/삭제를 담당하는 실행 엔진              |
| 동작  | kubelet이 CRI를 통해 Container Runtime에 명령 |
| 종류  | containerd (기본), CRI-O, Docker (지원 중단) |
| 필수성 | 필수, 없으면 Kubernetes 클러스터 동작 불가          |
---

## 주요 기능
| 역할          | 설명                             |
| ----------- | ------------------------------ |
| 컨테이너 생성     | Pod이 실행될 때 컨테이너 생성             |
| 컨테이너 시작     | 지정된 이미지로 컨테이너 실행               |
| 컨테이너 중지/삭제  | 종료된 컨테이너 정리                    |
| 이미지 다운로드    | 필요 시 Registry에서 이미지 pull       |
| 네트워크, 볼륨 연동 | CNI, CSI 플러그인과 연동하여 컨테이너 환경 세팅 |

- container runtime이 없다면?

| 현상              | 결과                        |
| --------------- | ------------------------- |
| containerd 비정상  | kubelet이 컨테이너 생성 불가       |
| 컨테이너 실행 요청 실패   | Pod이 Pending 상태에서 넘어가지 않음 |
| kubeadm init 실패 | CRI runtime 연결 에러 발생      |
---
## 동작 구조
```
[1] kubelet이 API Server로부터 "이 Pod을 실행해"라는 명령 받음

[2] kubelet이 Container Runtime에게 컨테이너 생성 요청

[3] Container Runtime이 이미지 pull -> 컨테이너 생성 -> 컨테이너 실행

[4] kubeletdl Container Runtime에게 상태 모니터링 요청

[5] 컨테이너가 종료되면 kubelet이 재시작 여부 판단
```
---
## 통신 구조
- kubernets와 container runtime가 통신하는 구조 : **CRI**를 통해 통신

| 계층                | 설명                                    |
| ----------------- | ------------------------------------- |
| kubelet           | 명령을 내림 (컨테이너 실행 요청)                   |
| CRI               | Container Runtime Interface (gRPC 기반) |
| Container Runtime | containerd, CRI-O, Docker (지원 중단)     |

```
[kubelet]
    │
    │ CRI (gRPC)
    ↓
[containerd]  or  [CRI-O]
    │
    ↓
[컨테이너 생성/실행]
```

## 종류
| Runtime        | 설명                                                 |
| -------------- | -------------------------------------------------- |
| **containerd** | Kubernetes 기본 표준, 가볍고 빠름                           |
| **CRI-O**      | OpenShift에서 많이 사용, 보안 강화, lightweight              |
| **Docker**     | Kubernetes 1.24부터 공식 지원 종료                         |
| **runc**       | containerd, CRI-O 내부에서 실제로 컨테이너를 실행하는 low-level 도구 |

- containerd의 주요 특징
  - docker 엔진의 핵심 모듈
  - kubernetes에서 가장 많이 사용
  - 성능 가볍고, kubernetes CRI와 직접 통신 가능
  - 기본 소켓: `unix:///var/run/containerd/containerd.sock`
<details>
<summary>🔽 [참고] Kubernetes가 Docker 지원을 중단한 이유</summary>

- Kubernetes는 Docker를 직접 지원하던 구조에서 → CRI 전용 지원 구조로 변경

- Docker는 CRI를 지원하지 않음 (Docker-shim이라는 중간 계층이 필요했음) → 비효율적

- Docker는 containerd를 내부적으로 사용하므로 → containerd를 직접 쓰는 것이 더 효율적

👉 Kubernetes 1.24부터 Docker 지원 완전 종료 (containerd 사용 권장)
</details>

## 주요 설정
- containerd config 경로:
  ```bash
  /etc/containerd/config.toml

  [root@master-node ~]# vi /etc/containerd/config.toml
      disabled_plugins = []
      imports = []
      oom_score = 0
      plugin_dir = ""
      required_plugins = []
      root = "/var/lib/containerd"
      state = "/run/containerd"
      temp = ""
      version = 2

      [cgroup]
      path = ""

      [debug]
      address = ""
      format = ""
      gid = 0
      level = ""
      uid = 0

      [grpc]
      address = "/run/containerd/containerd.sock"
      gid = 0
      max_recv_message_size = 16777216
      max_send_message_size = 16777216
      tcp_address = ""
      tcp_tls_ca = ""
      tcp_tls_cert = ""
      tcp_tls_key = ""
      uid = 0

      [metrics]
      address = ""
      grpc_histogram = false

      [plugins]

      [plugins."io.containerd.gc.v1.scheduler"]
      deletion_threshold = 0
      mutation_threshold = 100
      pause_threshold = 0.02
      schedule_delay = "0s"
      startup_delay = "100ms"

      [plugins."io.containerd.grpc.v1.cri"]
      device_ownership_from_security_context = false
      disable_apparmor = false
      disable_cgroup = false
      disable_hugetlb_controller = true
  ```
