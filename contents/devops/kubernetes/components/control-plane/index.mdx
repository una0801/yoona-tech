## 개념
- 쿠버네티스 클러스터 전체의 '두뇌'역할
- 클러스터 상태를 유지하고 조정하는 모든 핵심 로직 담당

| 노드 유형                              | 역할                                      | Pod 실행 가능?             |
| ---------------------------------- | --------------------------------------- | ---------------------- |
| 🧠 **Master Node (Control Plane)** | API Server, Controller, Scheduler, etcd | 기본적으로 ❌ (Taint로 막혀 있음) |
| ⚙️ **Worker Node**                 | 실제 앱(Pod)이 배포되는 공간                      | ✅ YES                  |

---

## 주요 기능
| 역할                 | 설명                               |
| ------------------ | -------------------------------- |
| 클러스터 상태 관리         | 어떤 Pod가 어디에 있고, 어떤 리소스를 사용하는지 추적 |
| 오브젝트 생성/삭제/업데이트 처리 | kubectl로 생성된 YAML을 실제 상태로 반영     |
| 스케줄링               | 새 Pod를 어떤 Node에 배치할지 결정          |
| 상태 조정              | 클러스터의 실제 상태를 원하는 상태로 유지          |
| API 인터페이스 제공       | 사용자, 내부 컨트롤러, 외부 시스템과의 통신 처리     |
---
## 전체 흐름 요약
```
[1] kubectl apply -f pod.yaml  ← 사용자가 원하는 상태 정의
        ↓
[2] API Server가 수신 → etcd에 저장
        ↓
[3] Controller Manager가 watch → 실제 상태와 비교
        ↓
[4] 필요시 Pod 생성 요청 → API Server → etcd
        ↓
[5] Scheduler가 해당 Pod를 적절한 Node에 배치
        ↓
[6] kubelet이 Pod 실행 → 상태 주기적 보고
```
