## 경계 보안의 종말

전통 보안은 "성벽(방화벽) 안은 안전, 밖은 위험"이라는 **경계(perimeter) 모델**이었다. 클라우드·원격근무·MSA 시대엔 안이 곧 밖이라 이 가정이 무너졌다.

<Compare>
<CompareCol title="🏰 경계 모델 (옛날)" subtitle="castle-and-moat" color="amber">
- 내부망에 들어오면 **암묵적 신뢰**
- 한 번 뚫리면 내부 자유 이동(lateral movement)
- VPN으로 "안"에 들어가면 끝
</CompareCol>
<CompareCol title="🛡️ 제로 트러스트" subtitle="never trust, always verify" color="violet">
- 위치(내부망) 기반 신뢰 **없음**
- 매 요청마다 신원·권한 **검증**
- 뚫려도 피해 최소(최소 권한·격리)
</CompareCol>
</Compare>

## AWS로 구현하기

| 원칙 | AWS 구성 요소 |
|------|------|
| 신원 중심 검증 | [IAM](/devops/aws/iam/iam-basics) · MFA · [Cognito](/devops/aws/iam/cognito) |
| 임시 자격증명 (장기 키 ❌) | [STS](/devops/aws/iam/sts) · 역할 기반 · OIDC |
| 키 없는 서버 접속 | [SSM Session Manager](/devops/aws/automation/ssm) (SSH·배스천 제거) |
| 마이크로 세그먼테이션 | 보안 그룹 · [PrivateLink](/devops/aws/security-deepdive/vpc-patterns) |
| 모든 구간 암호화 | [KMS](/devops/aws/security-deepdive/kms) · TLS · mTLS |
| 지속 감사 | [CloudTrail](/devops/aws/monitoring/cloudtrail) · [Config](/devops/aws/monitoring/config) |

<KeyPoint title="제로 트러스트는 제품이 아니라 원칙">
"이거 하나 사면 제로 트러스트"가 아니다. IAM·STS·SSM·PrivateLink·암호화·감사를
**최소 권한 + 항상 검증** 원칙으로 엮는 **설계 사고방식**이다.
</KeyPoint>

## 실천 체크리스트

<Note type="success" title="당장 할 수 있는 것">
- ✅ 루트 계정 MFA + 일상 사용 금지
- ✅ 장기 Access Key → STS 임시 자격증명·역할로 대체
- ✅ SSH 키·배스천 → SSM Session Manager
- ✅ 보안 그룹 최소 개방 (0.0.0.0/0 점검)
- ✅ 저장·전송 데이터 암호화 기본 ON
- ✅ CloudTrail 전 계정 + 이상 행위 알림
</Note>

<Note type="warning" title="오해 주의">
- "제로 트러스트 = VPN 제거"가 아니다 → **신뢰 모델 자체의 전환**
- 한 번에 완성 ❌ → 신원·세그먼트·감사를 단계적으로 강화
</Note>
