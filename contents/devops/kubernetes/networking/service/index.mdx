## Service 란?
- kubernetes에서 Pod을 **안정적으로 접근**하기 위한 **네트워크 엔트포인트**
- Pod이 몇 개든, 어디있든, 항상 동일한 IP와 DNS 이름으로 접근할 수 있게 해주는 가상 라우터
- 왜 필요할까?
  - Pod 은 어떤 상황에서
    - IP가 계속 바뀜 (Pod 재시작, Node 이동 시)
    - 이름이 고정되지 않음
  - Pod IP는 **휘발성!!** -> 그래서 고정된 접근 지점이 필요

| 항목    | 설명                                          |
| ----- | ------------------------------------------- |
| 정의    | Pod을 안정적으로 접근하기 위한 네트워크 객체                  |
| 핵심 기능 | 고정 IP 제공, 로드밸런싱, DNS 지원                     |
| 주요 유형 | ClusterIP, NodePort, LoadBalancer, Headless |
| 사용 예  | 애플리케이션 접근, DB 클러스터 관리, 외부 서비스 연결            |

---
## 핵심 기능

| 기능          | 설명                       |
| ----------- | ------------------------ |
| Pod의 IP 추상화 | Pod이 재시작돼도 고정된 접근 지점 제공  |
| 로드 밸런싱      | 여러 Pod 간 트래픽을 자동 분산      |
| 네임 서비스      | DNS 이름으로 접근 가능           |
| 포트 포워딩      | 외부 → 내부 Pod으로 네트워크 연결 가능 |

- DNS 이름 생성 규칙
```
<service-name>.<namespace>.svc.cluster.local

✔️ 예를 들어: backend-service.default.svc.cluster.local
✔️ 같은 네임스페이스라면 → 그냥 http://backend-service로 접속 가능
```

## 종류

| Service Type    | 설명                       | 사용 목적                |
| --------------- | ------------------------ | -------------------- |
| ClusterIP (기본값) | 클러스터 내부에서만 접근 가능         | 내부 통신                |
| NodePort        | Node의 특정 포트를 외부에 개방      | 외부 접근                |
| LoadBalancer    | 클라우드 로드밸런서 자동 생성         | 외부 접근 (클라우드 환경)      |
| ExternalName    | 외부 DNS를 내부로 매핑           | 외부 서비스 연결            |
| Headless        | 가상 IP 미사용, Pod DNS 직접 접근 | StatefulSet, DB 클러스터 |

## 동작 방식
```
[ Client (Pod or Node) ]
        |
        v
[ Service (ClusterIP or NodePort) ]
        |
        v
[ Pod 1 ]  [ Pod 2 ]  [ Pod 3 ]  (kube-proxy가 로드밸런싱)

✔️ service -> kube-proxy -> iptables or ipvs -> 실제 Pod 선택
```

- 상태 확인
```bash
kubectl get svc
kubectl describe svc <service-name>
kubectl get endpoints <service-name>

✔️ endpoints: 현재 연결된 실제 Pod IP 목록 확인 가능
```

## 예시
- ClusterIP YAML
```yaml
apiVersion: v1
kind: Service
metadata:
  name: backend-service
spec:
  selector:
    app: backend
  ports:
  - port: 8000
    targetPort: 8000

✔️ selector로 app : backend 라벨을 가진 Pod을 찾아서 연결
✔️ 기본적으로 ClusterIP : 클러스터 내부에서만 접근 가능
```
- NodePort YAML
```yaml
apiVersion: v1
kind: Service
metadata:
  name: frontend-service
spec:
  type: NodePort
  selector:
    app: frontend
  ports:
  - port: 80
    targetPort: 80
    nodePort: 30080

✔️ 클러스터 외부에서 NodeIP: 30080 으로 접근 가능
```
- LoadBalancer YAML
```yaml
apiVersion: v1
kind: Service
metadata:
  name: frontend-lb
spec:
  type: LoadBalancer
  selector:
    app: frontend
  ports:
  - port: 80
    targetPort: 80

✔️ 클라우드 환경에서 퍼블릭 로드밸런서 자동 생성
```
- Headless YAML
```yaml
apiVersion: v1
kind: Service
metadata:
  name: mongo
spec:
  clusterIP: None
  selector:
    app: mongo
  ports:
  - port: 27017

✔️ 가상 IP를 생성하지 않음
✔️ 각 Pod의 DNS를 그대로 반환 -> statefulSet 필수 구성 요소
```
