- **SQL** → 관계형 DB에 질문하고 데이터 꺼내고 바꾸는 언어
- 핵심 한 문장 → 테이블(엑셀 시트)에서 **원하는 행·열을 골라(SELECT)** · **여러 시트를 합치고(JOIN)** · **묶어 집계(GROUP BY)**
- 작성 순서와 **실행 순서가 다름** → 헷갈리는 1순위 포인트

## 엑셀 VLOOKUP으로 이해하는 JOIN

- 엑셀에서 `주문` 시트의 `회원ID`로 `회원` 시트의 이름을 끌어오는 게 **VLOOKUP**
- SQL의 **JOIN** → 두 테이블을 **공통 키(회원ID)** 로 옆으로 붙여 한 줄로 만드는 것
- VLOOKUP은 한 칸씩 끌어오지만 JOIN은 **테이블 전체를 한 번에** 연결

<KeyPoint title="이 비유에서 가져갈 것">
JOIN = 공통 키로 두 시트를 옆으로 합치기 ·
GROUP BY = 같은 값끼리 묶어 한 줄로 요약하기 ·
WHERE는 묶기 전 필터 · HAVING은 묶은 뒤 필터
</KeyPoint>

## SELECT 한 줄 뜯어보기

```sql
SELECT   member_id, COUNT(*) AS order_count   -- 무엇을 보여줄지
FROM     orders                                -- 어느 테이블에서
WHERE    status = 'PAID'                        -- 묶기 전 행 필터
GROUP BY member_id                              -- 같은 회원끼리 묶기
HAVING   COUNT(*) >= 3                           -- 묶은 결과 필터
ORDER BY order_count DESC                        -- 정렬
LIMIT    10;                                     -- 상위 10개만
```

<Cards cols={3}>
<Card icon="🔎" title="WHERE">
묶기 **전** 개별 행 필터 · 집계함수(COUNT 등) 사용 불가
</Card>
<Card icon="📦" title="GROUP BY">
같은 값끼리 **한 줄로 묶음** · 회원별·날짜별 요약
</Card>
<Card icon="🧮" title="HAVING">
묶은 **후** 그룹 필터 · `COUNT(*) >= 3` 같은 집계 조건
</Card>
</Cards>

## JOIN 종류 한눈에

| 종류 | 의미 | 결과에 남는 행 | 실무 예시 |
|---|---|---|---|
| `INNER JOIN` | 양쪽 다 매칭되는 것만 | 교집합 | 주문 + 그 주문의 회원 (둘 다 있는 것) |
| `LEFT JOIN` | 왼쪽 전부 + 매칭되는 오른쪽 | 왼쪽 기준 전부 | 회원 전부 + 주문 (주문 없으면 NULL) |
| `RIGHT JOIN` | 오른쪽 전부 + 매칭되는 왼쪽 | 오른쪽 기준 전부 | LEFT 방향만 반대 · 잘 안 씀 |
| `FULL OUTER JOIN` | 양쪽 전부 | 합집합 | MySQL은 미지원 · UNION으로 우회 |
| `CROSS JOIN` | 모든 조합 | 곱집합(N×M) | 사이즈×색상 전체 조합 |

```sql
-- 주문 없는 회원까지 포함해서 주문 수 세기 → LEFT JOIN
SELECT   m.name, COUNT(o.id) AS cnt
FROM     members m
LEFT JOIN orders o ON o.member_id = m.id
GROUP BY m.id;
-- INNER JOIN이면 주문 0건 회원이 통째로 사라짐 → 의도와 다름
```

<Note type="warning" title="LEFT JOIN 흔한 함정">
- `LEFT JOIN` 후 `WHERE o.status = 'PAID'` → 오른쪽 NULL 행이 걸러져 **사실상 INNER JOIN으로 변질**
- 오른쪽 조건은 `ON` 절에 넣어야 LEFT 의미 유지 → `ON o.member_id = m.id AND o.status = 'PAID'`
</Note>

## DDL vs DML - 구조냐 데이터냐

<Compare>
<CompareCol title="🏗️ DDL" subtitle="Data Definition · 구조 정의" color="amber">
- `CREATE` · `ALTER` · `DROP` · `TRUNCATE`
- 테이블·컬럼·인덱스 등 **틀**을 다룸
- 대부분 **auto-commit** → 롤백 안 됨(주의)
- `TRUNCATE` → 전체 삭제 + 구조 유지, `DELETE`보다 빠름
</CompareCol>
<CompareCol title="✏️ DML" subtitle="Data Manipulation · 데이터 조작" color="sky">
- `SELECT` · `INSERT` · `UPDATE` · `DELETE`
- 행(데이터) **내용**을 다룸
- 트랜잭션으로 묶어 **롤백 가능**
- `WHERE` 빠진 `UPDATE`/`DELETE` → 전체 변경(대형 사고)
</CompareCol>
</Compare>

## 작성 순서 ≠ 실행 순서

- 우리가 쓰는 순서는 `SELECT ... FROM ... WHERE ...`지만 DB가 처리하는 순서는 다름

```mermaid
flowchart LR
    F["FROM / JOIN<br/>테이블 결합"] -->|"행 모음"| W["WHERE<br/>행 필터"]
    W -->|"걸러진 행"| G["GROUP BY<br/>묶기"]
    G -->|"그룹"| H["HAVING<br/>그룹 필터"]
    H -->|"통과 그룹"| S["SELECT<br/>열 선택·별칭"]
    S -->|"결과 행"| O["ORDER BY<br/>정렬"]
    O -->|"정렬됨"| L["LIMIT<br/>잘라내기"]
```

<Note type="pink" title="실행 순서가 설명해주는 것들">
- `SELECT`에서 만든 **별칭(alias)을 WHERE에서 못 씀** → WHERE가 SELECT보다 먼저 실행되니까
- 별칭은 `ORDER BY`에선 사용 가능 → ORDER BY는 SELECT 뒤에 실행
- `WHERE`엔 집계함수 못 쓰고 `HAVING`엔 쓸 수 있음 → GROUP BY 전후 차이
- `LIMIT`이 마지막 → 정렬까지 다 끝난 뒤 잘라냄(상위 N개)
</Note>
