## Credentials
RAG 파이프라인에서 외부 모델/레지스트리(API)에 접근하려면 자격증명 설정 필요
- Hugging Face Access Token (HF_TOKEN)
- OpenAI API Key (OPENAI_API_KEY)
- 환경변수(.env), Docker Compose, Kubernetes Secret로 안전하게 주입하는 방법
- TEI / vLLM에서 토큰을 실제로 쓰는 위치와 테스트 방법
- 보안 Best Practices
---
## 어떤 토큰이 필요할까?

| 목적 | 필요한 자격증명 | 비고 |
|---|---|---|
| 임베딩(TEI)에서 **비공개 모델**/대역폭 우대 사용 | **HF_TOKEN** | 퍼블릭 모델만 쓸 땐 없어도 됨(권한에 따라 다름) |
| LLM 호출(대안)로 **OpenAI API** 사용 | **OPENAI_API_KEY** | vLLM이 아닌 OpenAI API를 직접 사용할 때 |
| 모델/이미지 **프라이빗 레지스트리** | 레지스트리 크리덴셜 | Docker Hub / GHCR / ECR 등 |

> vLLM/TEI 자체는 **OpenAI 호환 API 서버**이므로 _서버를 띄우기 위해_ OpenAI 키는 필요 ❌
> 다만 “OpenAI 모델을 직접 호출”하는 선택지를 쓸 때는 OPENAI_API_KEY가 필요

## 환경변수 관리(로컬)
1. `.env` 파일 (root에 생성)
   - .env는 git에 커밋 금지: .gitignore에 .env 추가
   ```
   # Hugging Face
   HF_TOKEN=hf_xxx_your_token

   # OpenAI (선택)
   OPENAI_API_KEY=sk-xxx

   # Service URLs (앱에서 쓸 경우)
   TEI_URL=http://localhost:8080
   QDRANT_URL=http://localhost:6333
   VLLM_URL=http://localhost:8000
   COLLECTION=docs
   EMBED_DIM=384
   TOP_K=3
   ```
2. shell에서 일시 설정(세션 한정)
   ```bash
   export HF_TOKEN="hf_xxx_your_token"
   export OPENAI_API_KEY="sk-xxx"
   ```

## Docker compose 
1. `docker-compose.yml`에서 참조
   - `.env` 파일이 같은 디렉토리에 있으면 compose가 자동으로 로드
   - 민감값은 반드시 `.env` 에서만 관리하고 YAML에는 `${...}` 참조만!
   ```yaml
    version: "3.8"
    services:
      tei:
        image: ghcr.io/huggingface/text-embeddings-inference:cpu
        command: >
          --model-id BAAI/bge-small-en-v1.5
        environment:
          - HF_TOKEN=${HF_TOKEN}
        ports:
          - "8080:80"

      vllm:
        image: vllm/vllm-openai:latest
        command: >
          --model TinyLlama/TinyLlama-1.1B-Chat-v1.0
          --device cpu
        ports:
          - "8000:8000"
   ```

## Kubernetes에서 주입
1. Secret 생성
  ```bash
  kubectl create secret generic ai-credentials \
  --from-literal=HF_TOKEN=hf_xxx_your_token \
  --from-literal=OPENAI_API_KEY=sk-xxx \
  -n ai
  ```
2. Secret 매니페스트(YAML, base64 인코딩 필요)
  ```bash
  apiVersion: v1
  kind: Secret
  metadata:
    name: ai-credentials
    namespace: ai
  type: Opaque
  data:
    HF_TOKEN: aGZfeHh4X3lvdXJfdG9rZW4=      # echo -n 'hf_xxx_your_token' | base64
    OPENAI_API_KEY: c2steHh4             # echo -n 'sk-xxx' | base64
  ```
3. Deployment 주입 (envForm or env)
  ```yaml
  apiVersion: apps/v1
  kind: Deployment
  metadata:
    name: tei
    namespace: ai
  spec:
    replicas: 1
    selector: { matchLabels: { app: tei } }
    template:
      metadata: { labels: { app: tei } }
      spec:
        containers:
        - name: tei
          image: ghcr.io/huggingface/text-embeddings-inference:cpu
          args: ["--model-id", "BAAI/bge-small-en-v1.5"]
          envFrom:
          - secretRef:
              name: ai-credentials
          ports:
          - containerPort: 80
  ---
  apiVersion: apps/v1
  kind: Deployment
  metadata:
    name: vllm
    namespace: ai
  spec:
    replicas: 1
    selector: { matchLabels: { app: vllm } }
    template:
      metadata: { labels: { app: vllm } }
      spec:
        containers:
        - name: vllm
          image: vllm/vllm-openai:latest
          args: ["--model", "TinyLlama/TinyLlama-1.1B-Chat-v1.0", "--device", "cpu"]
          envFrom:
          - secretRef:
              name: ai-credentials
          ports:
          - containerPort: 8000
  ```

## 토큰 사용 위치
1. TEI
  - 프라이빗 모델 다운로드/캐시, 레이트리밋 우대 등 HF Hub 접근
  - 사용 방법
     - 환경변수 : `HF_TOKEN`
     - Docker : `-e HF_TOKEN=$HF_TOKEN`
     - K8s : Secret 주입 -> `envFrom`
  - 확인
    ```bash
    curl -s http://localhost:8080/health && echo

    curl -s http://localhost:8080/v1/embeddings \
      -H "Content-Type: application/json" \
      -d '{
        "model": "BAAI/bge-small-en-v1.5",
        "input": ["hello world", "vector search is cool"]
      }' | jq '.data[0].embedding | length'
    ```
2. vLLM
   - vLLM 자체는 외부 토큰 필요 없음
   - OpenAI 키는 **vLLM 대신 OpenAI API를 직접 호출할 때**만 필요
   - vLLM 헬스체크 & 테스트
    ```bash
    curl -s http://localhost:8000/health && echo

    curl -s http://localhost:8000/v1/chat/completions \
      -H "Content-Type: application/json" \
      -d '{
        "model": "TinyLlama/TinyLlama-1.1B-Chat-v1.0",
        "messages": [{"role":"user","content":"Say hello"}]
      }' | jq '.choices[0].message.content'
    ```

## 앱 코드에서 읽기(예시)
- 대부분의 HF 호스팅 / Hub 접근은 Authorization 헤더로도 가능. (TEI는 env 전달로 충분)
```python
import os

HF_TOKEN = os.getenv("HF_TOKEN")
OPENAI_API_KEY = os.getenv("OPENAI_API_KEY")
TEI_URL = os.getenv("TEI_URL", "http://localhost:8080")
VLLM_URL = os.getenv("VLLM_URL", "http://localhost:8000")

# 필요시 requests 헤더에 추가
headers = {}
if HF_TOKEN:
  headers["Authorization"] = f"Bearer {HF_TOKEN}"
```

## 보안 Best Practice
- 소스 저장소에 토큰 하드코딩 금지: `.env` / `K8s Secret` / CI 변수로 관리
- 권한 최소화: HF/클라우드 키는 읽기 전용 스코프로 발급
- 회전 주기: 키 유출 가능성을 가정하고 주기적 Key Rotation
- 로그/에러에 토큰 출력 금지
- 프로덕션: 시크릿 매니저 권장
  - AWS Secrets Manager / Parameter Store
  - HashiCorp Vault
  - `sops + git` (KMS와 연계한 암호화)

## 트러블슈팅
- 401/403 Unauthorized: 토큰 오타, 권한 스코프 미달, 프라이빗 모델 접근 권한 확인
- 429 Too Many Requests: HF/오픈 API rate limit → 토큰 사용/유료 플랜 또는 로컬 캐시
- 모델 다운로드 지연: 최초 1회 캐시까지 시간 오래 걸림 → 이미지 레이어/볼륨 캐시 고려
- K8s에서 환경변수 미주입: `envFrom.secretRef.name` 오타, 네임스페이스 불일치 확인
