## Event Hooks 란?
  - FastAPI 애플리케이션이 시작하거나 종료될 때 실행되는 특별한 훅
  - 앱 전역 리소스를 초기화하거나 안전하게 정리하는 용도
  - 요청/응답 단위가 아닌 애플리케이션 전체 생명주기 단위에서 필요한 로직을 넣는 곳
  - 대표 시점
    - `startup` : 애플리케이션 부팅 시 (DB 풀 생성, 캐시 warm-up, 작업 큐 연결 등)
    - `shutdown` : 서버가 내려갈 때 (DB/Redis 연결 종료, 워커 정리, 파일 flush 등)
    - `lifespan` : 위 두 이벤트를 한꺼번에 관리할 수 있는 최신 권장 방식

## 사용
1. startup / shutdown
```python
from fastapi import FastAPI

app = FastAPI()

@app.on_event("startup")
async def startup_event():
    print("앱 시작: DB 연결 풀 초기화")

@app.on_event("shutdown")
async def shutdown_event():
    print("앱 종료: DB 연결 풀 닫기")
```
- `@app.on_event("startup")` : 앱 시작 시 실행
  - 데이터베이스 풀 생성 (`asyncpg.create_pool`)
  - Redis/MQ 연결
  - 설정값 캐싱, warm-up
- `@app.on_event("shutdown")` : 앱 종료 시 실행
  - 풀/연결 종료
  - 큐 graceful stop
  - 로그 flush
- async/sync 함수 모두 지원
2. lifespan
- FastAPI 0.95+ 에서는 lifespan 파라미터로 startup/shutdown을 한곳에서 관리하는 것이 권장
```python
from fastapi import FastAPI
from contextlib import asynccontextmanager
import asyncpg

db_pool = None

@asynccontextmanager
async def lifespan(app: FastAPI):
    global db_pool
    # startup
    db_pool = await asyncpg.create_pool(dsn="postgresql://user:pass@db:5432/app")
    print("DB 연결 풀 생성 완료")
    yield   # 여기까지 실행되면 앱이 살아있음
    # shutdown
    await db_pool.close()
    print("DB 연결 풀 종료 완료")

app = FastAPI(lifespan=lifespan)

@app.get("/users")
async def list_users():
    async with db_pool.acquire() as conn:
        rows = await conn.fetch("SELECT * FROM users")
        return rows

# 동기 버전
from contextlib import contextmanager
from fastapi import FastAPI

@contextmanager
def lifespan(app: FastAPI):
    print("Startup")
    yield
    print("Shutdown")

app = FastAPI(lifespan=lifespan)
```
- startup/shutdown 로직이 한 함수에 모여있어 가독성 ⬆️
- `yield` 전/후로 startup/shutdown을 직관적으로 구분
- 테스트 시에도 `lifespan` 컨텍스트를 쉽게 재사용 가능

## 실전 패턴
1. DB 연결 관리
   - 앱 시작 시 연결 풀 생성
   - 앱 종료 시 풀 close
2. 메시지 큐/캐시
   - Redis, Kafka, RabbitMQ 연결 생성/종료
3. 백그라운드 태스크 관리
   - 앱 부팅 시 주기적 태스크 등록
   - 앱 종료 시 스케쥴러/워커 graceful shutdown
4. 애플리케이션 warm-up
   - 모델 로딩 (ML/AI 서비스)
   - 설정값 캐싱
   - 외부 API 헬스 체크

## 주의 사항
1. lifespan vs on_event
   - `@app.on_event("startup"/"shutdown")` 도 여전히 지원되지만,FastAPI 최신 버전에서는 lifespan 방식 권장.
2. async 작업 주의
   - `asyncio.create_task()`로 백그라운드 루프 태스크를 돌리면 앱 종료 시 반드시 `task.cancel()`로 정리
3. 테스트 시
   - `TestClient(app)`는 lifespan 훅을 자동으로 실행/정리
   - DB 초기화/정리 코드가 테스트와 충돌하지 않게 주의
4. gunicorn/uvicorn 프로세스 모델
   - 워커마다 별도 실행되므로, startup/shutdown은 각 워커 프로세스 단위에서 실행
   - 공유 리소스(파일, 캐시) 초기화 로직은 멱등하게 작성해야 안전
