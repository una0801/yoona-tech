## 실행 구조
```
      +----------------+
      | Docker Image   |  <-- 여러 레이어 (읽기 전용)
      +----------------+
            |
            v
  +------------------------+
  | Container (실행 중)     |  <-- 실행 인스턴스
  | - PID Namespace       |  <-- 프로세스 격리
  | - Network Namespace   |  <-- 네트워크 격리
  | - Filesystem (OverlayFS) |  <-- 루트 파일시스템 격리
  | - User Namespace      |  <-- UID/GID 격리
  | - Mount Namespace     |  <-- 마운트 격리
  | - IPC Namespace       |  <-- IPC 격리
  +------------------------+

  1. Docker/Containerd가 이미지를 읽고 OverlayFS로 조합
  2. Namespace로 격리된 환경을 생성 (PID, Network, Mount 등)
  3. cgroups 를 통해 CPU, Memory 등 리소스 제어
  4. 컨테이너 프로세스가 실행됨 (ex. nginx, kafka 등)
```
  - 컨테이너 = 격리된 프로세스 그룹
  - 컨테이너는 **리눅스 커널**을 공유하면서 그 위에서 **독립된 실행환경** 제공
---
## Linux Namespace
- Namespace : 리눅스에서 프로세스를 격리하는 방법
- docker나 kubernetes 에서 사용하는 주요 네임스페이스 : 
  | Namespace 종류 | 역할                                               |
  | ------------ | ------------------------------------------------ |
  | **PID**      | 컨테이너 내부에서 `ps`, `top` 실행 시 자기 자신 프로세스만 보임        |
  | **Network**  | IP, 포트, 라우팅 테이블을 분리 (컨테이너마다 고유한 NIC 가상 인터페이스 생성) |
  | **Mount**    | 파일시스템 마운트를 분리 (루트 파일시스템을 격리)                     |
  | **UTS**      | 호스트 이름, 도메인 이름 분리 (`hostname` 명령어 결과 다름)         |
  | **IPC**      | 쉐어드 메모리, 세마포어 등의 IPC 리소스 분리                      |
  | **User**     | UID/GID 분리 (컨테이너 안에선 `root`지만 실제 호스트에선 일반 사용자)   |

- 결과적으로 컨테이너는 마치 독립된 OS처럼 행동하지만, 실제로는 호스트 OS위의 격리된 프로세스
---
## Control Groups(cgroups)
- 리눅스 커널 기능으로, 리소스 사용을 제한하고 모니터링 가능
- 컨테이너가 `OOMKilled` 되는 경우 대부분 memory cgroup에 의한 것
- cgroups로 제한 가능한 항목 :
  | 리소스 종류    | 설명                       |
  | --------- | ------------------------ |
  | CPU       | CPU time 할당량 제한, 우선순위 조정 |
  | Memory    | 메모리 사용량 제한 (OOM 방지)      |
  | Block I/O | 디스크 읽기/쓰기 속도 제한          |
  | Network   | 네트워크 대역폭 제한 (v2부터 가능)    |
  | PIDs      | 생성 가능한 프로세스 수 제한         |

## OverlayFS(파일시스템 구조)
- 컨테이너는 읽기 전용 이미지 레이어 위에 쓰기 가능한 컨테이너 레이어를 덧붙여서 작동
  ```
  OverlayFS 구조
  -----------------------------
  Writable Layer   ← 컨테이너가 변경한 파일들
  -----------------------------
  Image Layer N
  Image Layer N-1
  ...
  Base Image Layer (예: ubuntu)
  -----------------------------
  ```
  - 변경한 파일은 writable layer에만 기록됨 (Copy-on-Write 방식)
  - 여러 컨테이너가 같은 이미지 레이어를 공유 -> 디스크 절약
---
## 핵심요약
| 구성 요소     | 설명                             |
| --------- | ------------------------------ |
| Namespace | 격리를 통해 각 컨테이너가 독립된 환경처럼 보이게 만듦 |
| cgroups   | 자원 사용 제한 및 제어                  |
| OverlayFS | 파일시스템을 이미지 레이어 + 쓰기 레이어로 구성    |
| 커널 공유     | 실제 커널은 호스트 OS와 공유되어 성능 향상      |
