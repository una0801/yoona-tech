- **CPU** → 실제로 계산·판단을 하는 부품 → 컴퓨터의 "뇌"
- **메모리** → CPU가 지금 쓸 데이터·명령어를 잠깐 올려두는 작업 공간
- 한 줄 요약 → CPU는 **계산만**, 데이터는 가까울수록(레지스터) 빠르고 멀수록(디스크) 느림

## 요리사와 작업대로 이해하기

- **CPU = 요리사** → 재료를 직접 썰고 볶는 사람 (계산 담당)
- **레지스터 = 요리사 양손** → 지금 당장 쥐고 있는 재료 → 제일 빠름, 대신 두 손뿐 (아주 작음)
- **캐시 = 도마 위** → 손 바로 옆, 금방 집음
- **메모리(RAM) = 작업대** → 조금 떨어진 조리대, 손 뻗어야 함
- **디스크(SSD/HDD) = 냉장고/창고** → 멀리 있어 다녀와야 함 → 제일 느림

<KeyPoint title="이 비유에서 가져갈 것">
CPU는 양손(레지스터)으로만 직접 일함 · 멀리 있는 재료(디스크)는 작업대(메모리)로, 다시 양손(레지스터)으로 단계별로 끌어와야 씀 · 가까울수록 빠르고 작고, 멀수록 느리고 큼
</KeyPoint>

## CPU 3대 구성

<Cards cols={3}>
<Card icon="🧮" title="ALU">
산술논리연산장치 · 실제 **계산**(+ − × ÷)과 **비교**(>, ==, AND/OR) 담당 · 요리사의 칼질 손
</Card>
<Card icon="🎛️" title="제어장치(CU)">
명령어를 해석해 **누가 뭘 할지 지시** · ALU·레지스터·메모리에 신호 보냄 · 주방장 역할
</Card>
<Card icon="✋" title="레지스터">
CPU **안의 초소형 저장공간** · 지금 쓰는 값·중간 결과 보관 · 가장 빠름, 가장 작음
</Card>
</Cards>

- **ALU** → 시키는 계산만 빠르게 → 스스로 판단 안 함
- **제어장치** → "이 명령어는 덧셈이네 → ALU 켜고, 결과는 이 레지스터에 넣어" 식으로 지휘
- **레지스터** → 메모리보다 수십 배 빠름 → 대신 몇 개뿐 (양손)

## 폰노이만 구조

- 명령어(프로그램)와 데이터를 **같은 메모리**에 함께 저장 → 현대 컴퓨터의 기본 뼈대
- CPU는 메모리에서 명령어를 **하나씩 꺼내(fetch)** 실행 → 순서대로 처리

```mermaid
flowchart LR
    Mem["메모리<br/>명령어 + 데이터 함께"] -->|명령어/데이터 읽기| CPU["CPU<br/>ALU + 제어장치 + 레지스터"]
    CPU -->|계산 결과 쓰기| Mem
    IO["입출력 장치<br/>키보드·화면·디스크"] -->|입력| CPU
    CPU -->|출력| IO
```

- **장점** → 구조 단순 · 프로그램도 데이터처럼 다룸 (소프트웨어 교체 쉬움)
- **한계(병목)** → CPU와 메모리가 **하나의 통로**로 연결 → 명령어·데이터가 같은 길로 오가며 줄 섬 → 폰노이만 병목
- 이 병목을 줄이려고 → **캐시**·레지스터로 가까이 미리 당겨둠

## 메모리 계층 (빠름 → 느림)

- 빠른 저장장치는 비싸고 작음 · 느린 건 싸고 큼 → 그래서 **계단식**으로 쌓아 씀

<Layers>
<Layer title="레지스터" sub="CPU 내부 · 양손" color="rose">
약 1KB 미만 · 접근 ~1ns · 지금 당장 계산에 쓰는 값 · 가장 빠르고 가장 작음
</Layer>
<Layer title="캐시 (L1/L2/L3)" sub="CPU 옆 · 도마 위" color="pink">
수십 KB ~ 수십 MB · 접근 ~1~10ns · 자주 쓰는 메모리 내용 복사본 보관
</Layer>
<Layer title="메인 메모리 (RAM)" sub="작업대" color="amber">
수 GB ~ 수십 GB · 접근 ~100ns · 실행 중 프로그램·데이터 올려둠 · 전원 끄면 사라짐
</Layer>
<Layer title="보조기억장치 (SSD/HDD)" sub="냉장고·창고" color="green">
수백 GB ~ 수 TB · 접근 ~수만 ~ 수백만 ns · 파일·OS 영구 저장 · 전원 꺼도 유지
</Layer>
</Layers>

- 위로 갈수록 → **빠름·작음·비쌈** / 아래로 갈수록 → **느림·큼·쌈**
- CPU는 항상 **위 칸부터** 찾음 → 없으면 한 칸 아래로 내려가 가져옴

- → 데이터가 멀어질수록 비용이 **기하급수**로 커짐 → 가까이 두는 게 성능의 핵심

## 클럭과 코어

<Compare>
<CompareCol title="⏱️ 클럭 (속도)" subtitle="1초에 박자 몇 번" color="sky">
- 클럭 = CPU가 일하는 **박자(Hz)** · 3GHz → 1초에 30억 번
- 높을수록 명령어 하나하나 **빨리** 처리
- 너무 높이면 → 발열·전력 ⬆️ (한계 존재)
</CompareCol>
<CompareCol title="🧑‍🍳 코어 (인원)" subtitle="요리사 몇 명" color="green">
- 코어 = 독립적으로 일하는 **CPU 단위**
- 4코어 → 요리사 4명이 **동시에** 다른 요리
- 일을 나눌 수 있어야(병렬화) 효과 → 못 나누면 1명만 일함
</CompareCol>
</Compare>

<Note type="note" title="실무 한 줄">
- "GHz 높음 = 무조건 빠름" 아님 → 코어 수·캐시·작업 성격(병렬 가능 여부)이 같이 좌우
- 싱글 스레드 작업 → 클럭이 더 중요 / 다중 작업·서버 → 코어 수가 더 중요
- 메모리 계층 때문에 → "데이터를 어떻게 배치하느냐"가 같은 CPU에서도 속도를 크게 바꿈 ([캐시](/cs/architecture/cache) 참고)
</Note>
