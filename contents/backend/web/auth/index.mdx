## 인증 vs 인가
- 인증(Authentication) : "누구인지" 확인하는 과정 (로그인)
- 인가(Authorization) : "무엇을 할 수 있는지" 결정하는 과정 (권한 부여)
- 예시
  - 인증 : "이 사용자는 una801@naver.com 이다"
  - 인가 : "이 사용자는 관리자 권한이 있어서 /admin 페이지 접근이 가능하다"

## Session 기반 인증
1. 개념
   - 서버가 로그인 성공 시 **세션 ID**를 발급 -> 클라이언트 쿠키에 저장
   - 요청 시 쿠키의 세션 ID로 서버에서 사용자 상태 확인
   - **간단한 웹 로그인 (쿠키 기반)**
2. 장점
   - 구현 단순, 웹 브라우저와 친화적 (쿠키/세션 관리 자동)
   - 서버 측에서 사용자 상태를 직접 제어 가능
3. 단점
   - 서버에 세션 상태 저장 필요 -> 스케일아웃(멀티서버) 시 세션 공유 필요
   - 모바일/SPA 환경에서는 불편할 수 있음

## JWT
1. 개념
   - 로그인 시 서명된 토큰(JWT) 발급 -> 클라이언트가 보관
   - 요청 시 `Authorization: Bearer <token>` 헤더로 전달
   - 서버는 서명을 검증해 사용자 식별
   - **모바일/SPA/마이크로서비스 환경 (stateless)**
2. 구조
```json
{
  "sub": "user123",
  "exp": 1710000000
}
```
3. 장점
   - 서버에 세션 상태 저장 불필요 (stateless)
   - 분산 시스템/마이크로서비스에 적합
   - 토큰에 사용자 정보/권한 포함 가능
4. 단점
   - 토큰 크기가 큼 (헤더에 매번 포함)
   - 발급 후 취소 어려움 (블랙리스트 관리 필요)
   - 만료 전까지는 유효 -> 보안 주의 필요

## OAuth2
1. 개념
   - 제3자 인증/인가 프로토콜
   - 흔히 소셜 로그인(Google, GitHub 로그인) 등에 사용
   - Access Token을 발급받아 API 접근에 사용
   - **소셜 로그인, 권한 위임, 외부 API 연동**
2. 흐름
```
[1] 클라이언트가 사용장게 인증 요청
[2] 사용자가 인증 서버에서 로그인 -> 동의
[3] 클라이언트는 Authorization Code 획득
[4] Authorization Code를 인증 서버에 교환하여 Access Token 발급
[5] 이 후 API 호출 시 Authorization : Bearer <access_token>
```
3. 장점
   - 타사 서비스 계정으로 로그인 가능 (소셜 로그인)
   - 권한 범위 제어 가능 (ex. 메일 읽기만 허용)
   - 기업 환경에서 표준적으로 사용 (OpenID Conect 포함)
4. 단점
   - 구현이 복잡
   - 인증 서버/인가 서버 관리 필요
   - 모바일/SPA 환경에서는 보안 고려 필수

## API Key 기반 인증
1. 개념
   - 클라이언트가 발급받은 고유 키(API Key)를 요청에 포함
   - 보통 `Authorization: ApiKey <key>` 또는 쿼리 파라미터에 포함
   - **단순 서버 간 인증, 내부 API**
2. 장점
   - 구현 간단
   - 서버 간 통신, 공개 API, 내부 API에 적합
3. 단점
   - 키 탈취 위험
   - 권한 제어 한계 (세밀한 인가 불가)
   - 보통 사용자 인증 보다는 서비스 호출 인증용

## 비교

| 방식          | 상태 저장     | 적합한 환경            | 장점              | 단점              |
| ----------- | --------- | ----------------- | --------------- | --------------- |
| **Session** | 서버에 상태 저장 | 전통 웹, 브라우저 환경     | 단순, 쿠키 자동 관리    | 서버 확장 시 공유 필요   |
| **JWT**     | Stateless | 모바일/SPA, 분산 시스템   | 확장성, 권한 포함      | 취소 어려움, 토큰 크기 큼 |
| **OAuth2**  | Stateless | 소셜 로그인, 외부 서비스 연동 | 표준, scope 기반 인가 | 복잡도 높음          |
| **API Key** | Stateless | 서버-서버 통신, 간단한 API | 간단, 빠름          | 권한 제어 한계, 보안 취약 |
