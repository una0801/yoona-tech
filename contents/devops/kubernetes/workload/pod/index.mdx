## Pod 란?
- kubernetes에서 **배포 가능한 가장 작은 단위**
- 하나 이상의 컨테이너를 실행하는 **최소 실행 단위**

| 항목    | 설명                                |
| ----- | --------------------------------- |
| 정의    | Kubernetes의 최소 배포 단위              |
| 구성    | 하나 이상의 컨테이너, 공유 IP, 공유 볼륨         |
| 일반 사용 | 대부분 컨테이너 1개 사용                    |
| 생성 방법 | 보통 Deployment, StatefulSet을 통해 생성 |
| 스케줄링  | Scheduler가 Node에 Pod 할당           |
| 수명    | 불변 (immutable), 죽으면 새로 생성         |


---

## 내부 구조
```
[ Pod ]
 ├── [ Container 1 ] (보통 애플리케이션)
 ├── [ Container 2 ] (보조 컨테이너: sidecar)
 ├── [ Shared Volume ]
 └── [ Shared Network Namespace (IP, Port) ]

  ✔️ Pod 내부 컨테이너들은 localhost로 통신
  ✔️ Pod 간 통신은 service를 통해서만 가능 
```
---
## 주요 특징
| 항목      | 설명                                              |
| ------- | ----------------------------------------------- |
| 최소 단위   | Kubernetes에서 관리 가능한 가장 작은 단위                    |
| 컨테이너 그룹 | 하나 이상의 컨테이너를 포함할 수 있음 (보통 1개)                   |
| 동일 네트워크 | Pod 내 컨테이너들은 같은 IP, 같은 localhost 공유             |
| 공유 스토리지 | Pod 내 컨테이너들은 볼륨을 공유할 수 있음                       |
| 생성과 소멸  | Pod는 일반적으로 일회성, 재시작 시 새로운 Pod 생성 (immutable 개념) |

1. Pod 내 컨테이너들은 동일한 네트워크 공간을 공유
   - 같은 IP
   - 같은 포트 네임스페이스
   - localhost로 직접 통신 가능
2. Pod 내 볼륨 공유 가능
   - 여러 컨테이너가 같은 볼륨을 mount 할 수 있음
3. Pod는 일반적으로 한 개의 컨테이너 사용
   - Sidecar, Init Container가 필요할 경우 2개 이상 사용
4. Pod는 재시작 시 새로 생성됨
   - kubernetes는 Pod를 복제하지 않고 새 Pod를 새로 만듦 (UID 다름)
---
## 생성 흐름
```
[1] kubectl apply -f pod.yaml

[2] API Server가 요청 수신

[3] Scheduler가 Node에 할당

[4] kubelet이 Container Runtime 호출 -> 컨테이너 실행

[5] CNI가 네트워크 연결

[6] kubelet이 상태 업데이트
```
---

## 라이프사이클

| 단계        | 설명                            |
| --------- | ----------------------------- |
| Pending   | Pod이 스케줄 됐지만 Node에 아직 배치되지 않음 |
| Running   | Pod이 Node에서 실행 중              |
| Succeeded | Pod의 모든 컨테이너가 정상 종료           |
| Failed    | 컨테이너가 비정상 종료                  |
| Unknown   | kubelet과 통신 실패 시 발생           |

## 예시
- pod YAML
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  containers:
  - name: nginx
    image: nginx:latest
    ports:
    - containerPort: 80

  ✔️ 일반적으로 Pod는 직접 배포 X -> Deploymnet, DaemonSet, StatefulSet 이용
    -> pod은 복제, 롤백, 스케일링, 장애복구 기능이 없음
```
