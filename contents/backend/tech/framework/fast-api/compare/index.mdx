    ### 🚀 FastAPI - 비동기 기반 고성능 API 프레임워크
    **특징**
    - 비동기(Async) 기반으로 고성능 API 개발 가능
    - 자동 문서화 (Swagger UI, ReDoc) 지원
    - Pydantic을 활용한 데이터 검증 제공
    - WebSocket, GraphQL 기본 지원
    - OAuth2 및 JWT 인증 가능

    **주요 기능**
    ```python
    from fastapi import FastAPI
    from pydantic import BaseModel

    app = FastAPI()

    class Item(BaseModel):
        name: str
        price: float

    @app.post("/items/")
    async def create_item(item: Item):
        return item
    ```

  </TabsContent>

  <TabsContent value="django">
    ### ⚙️ Django - 풀스택 웹 애플리케이션 프레임워크
    **특징**
    - ORM(Object-Relational Mapping) 제공
    - Django Admin 패널 기본 제공
    - 강력한 보안 기능 내장 (CSRF, XSS 방어)
    - 웹 애플리케이션과 API를 함께 개발 가능

    **주요 기능**
    ```python
    from django.db import models

    class Item(models.Model):
        name = models.CharField(max_length=100)
        price = models.FloatField()
    ```
  </TabsContent>

  <TabsContent value="flask">
    ### 🏗 Flask - 경량 마이크로 프레임워크
    **특징**
    - 최소한의 코드로 빠른 개발 가능
    - ORM 미제공 (SQLAlchemy 사용 가능)
    - 확장성이 높아 필요한 기능을 자유롭게 추가 가능
    - Jinja2 템플릿 시스템 지원

    **주요 기능**
    ```python
    from flask import Flask, request, jsonify

    app = Flask(__name__)

    @app.route("/items", methods=["POST"])
    def create_item():
        data = request.json
        return jsonify(data)
    ```

  </TabsContent>

## 사용

### FastAPI
- 타입 힌트 기반으로 **자동 문서화**와 **데이터 검증**이 가능하여 개발 속도가 빠름
- **비동기(Async) 개념을 익혀야 하지만**, 사용성이 우수함
- Django보다 배우기 쉽고, Flask보다 구조적

### Django
- ORM, Admin 패널, 사용자 인증 등 **기능이 많아 초보자가 접근하기 어려울 수 있음**
- 하지만 한 번 익히면 **웹 개발을 빠르고 강력하게 진행할 수 있음**
- 데이터베이스 모델링과 관리가 강력함

### Flask
- 가장 배우기 쉬운 프레임워크
- 최소한의 코드로 개발이 가능하지만, ORM, 인증 등을 직접 추가해야 함
- **유연성이 높지만, 규모가 커질수록 코드 관리가 어려워질 수 있음*

## 비동기

| 비교 항목       | FastAPI (ASGI) | Flask (WSGI) | Django (기본 WSGI) | Django (ASGI 모드) |
|----------------|--------------|-------------|----------------|----------------|
| **비동기 지원** | ✅ 완벽 지원 | ❌ 미지원 (기본) | ❌ 기본 미지원 | ✅ 지원 가능 (ASGI 모드) |
| **성능**       | 🚀 매우 빠름 | 🐢 느림 (싱글 스레드) | 🐢 느림 (싱글 스레드) | 🚀 ASGI로 최적화 가능 |
| **데이터베이스** | ✅ 비동기 ORM 지원 | ❌ 동기 ORM만 가능 | ❌ 동기 ORM만 가능 | ✅ 비동기 ORM 사용 가능 |
| **웹소켓 지원** | ✅ 지원 | ❌ 미지원 | ❌ 미지원 | ✅ 지원 가능 |
| **추천 용도**  | 고성능 API 서버, 실시간 처리 | 간단한 API 서버 | 전통적인 웹 애플리케이션 | 비동기 웹 개발 |

  <TabsContent value="fastapi-pros">
    ### ✅ FastAPI 장점
    - **비동기 지원**으로 높은 성능 제공
    - 자동 문서화 및 Pydantic을 활용한 **강력한 데이터 검증**
    - WebSocket 및 GraphQL 기본 지원
    - **REST API 개발이 빠르고 효율적**

    ### ❌ FastAPI 단점
    - ORM이 내장되어 있지 않아 SQLAlchemy 등의 ORM을 직접 추가해야 함
    - Django처럼 Admin 패널이 없어 직접 구축해야 함
    - 비동기 처리를 이해해야 함 (초보자에게는 다소 어려울 수 있음)
  </TabsContent>

  <TabsContent value="django-pros">
    ### ✅ Django 장점
    - ORM 및 Admin 패널 내장**으로 데이터베이스 연동이 강력
    - 보안 기능 기본 제공** (CSRF, XSS 방어, 권한 관리 등)
    - 웹 애플리케이션과 API를 동시에 개발 가능**

    ### ❌ Django 단점
    - 초기 설정이 복잡하고 학습 곡선이 높음
    - 비동기(Async)를 기본적으로 지원하지 않음 (ASGI 설정 필요)
    - API 개발보다는 **웹 애플리케이션 개발에 초점**이 맞춰져 있음
  </TabsContent>

  <TabsContent value="flask-pros">
    ### ✅ Flask 장점
    - 가장 가볍고 배우기 쉬운 프레임워크**
    - 필요한 기능을 직접 추가하는 **유연성 제공**
    - 빠른 프로토타이핑 및 소규모 프로젝트에 적합**

    ### ❌ Flask 단점
    - ORM, 인증, 보안 기능이 내장되어 있지 않아 직접 추가해야 함
    - API 규모가 커질수록 유지보수가 어려울 수 있음
    - 비동기(Async) 기능이 부족하여 FastAPI보다 성능이 떨어짐
  </TabsContent>
</Tabs>

## 어떤 프레임워크를 선택해야 할까?

- FastAPI (비동기 API 서버 구축)
  - 비동기 기반으로 **성능이 중요한 API 서비스** 개발
  - Swagger UI 자동 생성, 빠른 데이터 검증 필요할 때

- Django (ORM 및 Admin 패널이 필요한 대형 웹 서비스)
  - 데이터 모델이 복잡하고 **ORM이 강력해야 할 경우**
  - Admin 패널을 사용하여 **웹 관리 시스템이 필요한 경우**

- Flask (빠른 프로토타이핑 및 경량 API 개발)
  - 빠르고 가벼운 API 또는 웹 애플리케이션을 개발해야 할 경우
  - Django보다 자유로운 **구조로 개발하고 싶은 경우**
