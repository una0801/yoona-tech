## 개념
- model + view + controller

## 구조
- **Model** : 애플리케이션에서 사용되는 데이터와 그 데이터를 처리하는 부분
- **View** : 사용자에게 보여지는 UI 부분
- **Controller** : 사용자의 입력 (Action) 을 받고 처리하는 부분

## 동작
- (예시) : FastAPI에서는 전통적인 MVC 패턴처럼 명확하게 나누진 않지만 구조적으로 비슷한 방식으로 구성 가능
  
| 구성요소        | 역할  | FaspiAPI 구조 대응 |
|-------------|------------------------|--------------------------|
| **Model** | 데이터 및 비즈니스 로직| `SQLAlchemy` `pydantic`, DB 연동 등|
| **View**|  사용자에게 보여지는 부분 |API 응답(JSON)|
| **Controller** | 요청 처리, 라우팅 | FastAPI 라우터 함수 (엔드포인트)|

  1. 사용자의 Action 들은 Controller에 들어오게 됨
  2. Controller는 사용자의 Action을 확인하고, Model을 업데이트
  3. Controller는 Model을 나타내줄 View 선택
  4. View는 Model을 이용하여 화면을 나타냄

```
app/
├── main.py                 # 앱 실행
├── models/
│   └── user.py             # Model (DB 정의)
├── schemas/
│   └── user.py             # Model (Pydantic 스키마)
├── views/
│   └── user.py             # Controller (라우터)
├── services/
│   └── user_service.py     # 비즈니스 로직
└── database.py             # DB 연결
```

## 특징
- Controller는 여러개의 View를 선택할 수 있는 1:N 구조
- Controller는 View를 선택할 뿐 직접 업데이트 하지 않음

## 장단점
- 장점
  - MVC 패턴의 장점은 널리 사용되고 있는 패턴이라는 점에 걸맞게 단순함
  - 단순하다 보니 보편적으로 많이 사용되는 디자인패턴
- 단점
  - View와 Model 사이의 의존성이 높음
  - 높은 의존성은 어플리케이션이 커질수록 복합해지고 유지보수가 어렵게 만들 수 있음
