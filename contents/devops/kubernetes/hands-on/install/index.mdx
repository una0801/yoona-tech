---
<Note type="Warning" title="Note">
  Kubernetes v1.22 ~ v1.27까지는 실험적 기능(alpha/beta) 로
        v1.28부터는 Stable(정식) 기능으로 swap 사용이 허용
        | 항목          | 현재 요구사항                                                         | 설명                                                                              |
        | ----------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------- |
        | **SELinux** | ❗ **완전 비활성화는 더 이상 필수 아님**Permissive 또는 container 정책 적용 시 OK | `enforcing` 상태에서도 **대부분 작동하지만**, 일부 네트워크 플러그인(CNI)이나 CSI 플러그인은 **에러 발생 가능성 있음** |
        | **Swap**    | ✅ **비활성화는 더 이상 필수 아님**`fail-swap-on: false` 설정 시 사용 가능      | **v1.28부터 정식 지원됨**, 다만 성능/안정성 측면에서 **비활성화를 권장**                                 |

  ++ swap disable 하려면
  ```
  sudo swapoff -a && sudo sed -i '/swap/s/^/#/' /etc/fstab
  sudo systemctl stop firewalld (방화벽 해제)
  sudo systemctl disable firewalld
  ```
</Note>

## 설치 과정
<Stepper>
  <StepperItem title="1: Docker 설치">
  ```bash
    yum install -y yum-utils

    # 도커 repository 추가
    yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
    
    # 설치 시 충돌 나기 때문에 해당 파일 삭제
    yum remove -y podman
    yum remove -y buildah    

    yum install -y docker-ce docker-ce-cli containerd.io
    sudo systemctl start docker   
    ```
  </StepperItem>
  <StepperItem title="2: 설치환경 셋팅">
    ```bash
    1️⃣ SELinux 설정
     # 현재 적용 중인 SELinux 정책 확인
     getenforce

     # Permissive로 변겨
     sudo setenforce 0

     # 영구 설정
     sudo sed -i 's/^SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config
    
    2️⃣ Swap 비활성화 (⚠️ SELinux가 Enforcing이면 CNI 또는 kubelet 오류가 발생할 수 있음)
     sudo swapoff -a

     # /etc/fstab에서 swap 라인 주석 처리
     sudo sed -i '/swap/d' /etc/fstab

    3️⃣ 네트워크 설정 (브릿지 트래픽 + IP 포워딩)
     # 브릿지 설정
     cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
     br_netfilter
     EOF

     sudo modprobe br_netfilter 

     # sysctl 파라미터
     cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
     net.bridge.bridge-nf-call-ip6tables = 1
     net.bridge.bridge-nf-call-iptables = 1
     net.ipv4.ip_forward = 1
     EOF

     # 적용
     sudo sysctl --system
    
    4️⃣ containerd 설정
     # 기본 설정 생성
     sudo mkdir -p /etc/containerd
     containerd config default | sudo tee /etc/containerd/config.toml

     # systemd cgroup으로 변경
     sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml

     # containerd 시작
     sudo systemctl enable --now containerd
    ```
  </StepperItem>
  <StepperItem title="3: kubeadm / kubelet / kubectl 설치">
```bash
# 리포지토리 등록
cat <<EOF | sudo tee /etc/yum.repos.d/kubernetes.repo
[kubernetes]
name=Kubernetes
baseurl=https://pkgs.k8s.io/core:/stable:/v1.29/rpm/
enabled=1
gpgcheck=1
gpgkey=https://pkgs.k8s.io/core:/stable:/v1.29/rpm/repodata/repomd.xml.key
EOF

# 설치
sudo yum install -y kubelet kubeadm kubectl

# 자동 시작 설정
sudo systemctl enable --now kubelet
```
</StepperItem>
<StepperItem title="4: 호스트명 & hosts 파일 설정 (멀티노트 구성 시)">
```bash
# 모든 노드가 서로의 호스트명을 /etc/hosts 또는 DNS를 통해 인식 가능해야함
# 예: Master Node
sudo hostnamectl set-hostname master-node

# /etc/hosts
echo "192.168.140.19 master-node" | sudo tee -a /etc/hosts
```
</StepperItem>
<StepperItem title="5: Master Node 초기화">
```bash
# ✅ 마스터 노드에서만 수행
sudo kubeadm init --pod-network-cidr=10.244.0.0/16

# --pod-network-cidr는 사용하는 CNI에 따라 다름 (Flannel: 10.244.0.0/16)
# ⚠️ 성공하면 아래처럼 kubeadm join 명령어가 출력 → 워커 노드에서 사용해야 하므로 복사!
  (ex: kubeadm join 192.168.140.19:6443 --token h48oo3.laisaziwkt982lpv \
	--discovery-token-ca-cert-hash sha256:f5b621d653a63e7550992198fc0113503cbd6fd483a88684773717198a795d8c)
```
```bash
# 📍 만약 아래와 같은 에러 발생 시
[ERROR CRI]: container runtime is not running: output: time="2025-06-19T01:54:54-04:00" 
level=fatal msg="validate service connection: validate CRI v1 runtime API for endpoint
 \"unix:///var/run/containerd/containerd.sock\": rpc error: code = Unimplemented desc 
 = unknown service runtime.v1.RuntimeService"
, error: exit status 1

✔️ 원인
1. config.toml 이 정상 생성되지 않음(수동으로 복사하거나 잘못된 형식)
2. containerd가 CRI plugin을 enable 하지 못하고 있음
3. RHEL 계열에서는 EPEL이나 docker repo의 오래된 containerd 패키지를 설치한 경우,
Kubernetes의 CRI와 버전 호환이 안 될 수 있음

✔️ 해결방안 : containerd 설정 파일 완전 재생성
sudo rm -f /etc/containerd/config.toml

# 새로 생성 (공식 기본 설정)
containerd config default | sudo tee /etc/containerd/config.toml > /dev/null

# SystemdCgroup = true 설정 다시 적용
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml

# containerd 재시작
sudo systemctl daemon-reexec
sudo systemctl restart containerd

# 상태확인
sudo ctr version
-> 정상적으로 출력되면 OK
-> 이후 다시 kubeadm 실행
```
</StepperItem>

<StepperItem title="8: 설치확인 (마스터 노드)">
```bash
[root@master-node ~]# kubectl get nodes
NAME          STATUS   ROLES           AGE     VERSION
master-node   Ready    control-plane   36m     v1.29.15
worker-node   Ready    <none>          3m24s   v1.29.15

📌 참고: 이 Role은 단순 "표시" -> kubectl get nodes에서 보기 좋게 하기 위한 역할
✔️ worker-node Roles가 None 인 이유 :
kubeadm join을 사용해서 워커 노드를 클러스터에 붙이면,
Kubernetes는 기본적으로 "Role" 라벨을 자동으로 설정하지 않음
-> 마스터 노드는 kubeadm init 시 자동으로 node-role.kubernetes.io/control-plane 라벨이 붙음
워커 노드는 따로 라벨을 붙이지 않기 때문에 <none> 으로 보임

✔️ 만약 라벨을 붙히고 싶다면?
kubectl label node worker-node node-role.kubernetes.io/worker=""

- worker-node: 노드 이름
- node-role.kubernetes.io/worker: Role 이
- 값은 "" (빈 문자열)
```
</StepperItem>
