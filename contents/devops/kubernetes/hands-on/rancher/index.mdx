## rancher란?
 - 여러 개의 kubernentes 클러스터를 중앙에서 관리하고 사용자/권한/앱 배포까지 UI로 통합 관리할 수 있게 해주는 관리 플랫폼
 - 쿠버네티스 클러스터 전체를 제어하는 상위 플랫폼
 - 사용 예 : 
   - 회사 내부에 2개 이상 kubernentes 클러스터가 존재
   - 개발자들이 직접 배포하고싶음 (self-service)
   - 운영팀의 쿠버네티스 직접 접근 권한을 최소하하고 싶을 때
   - EKS / AKS / GKE 클러스터를 한 곳에서 보고싶을 때
   - Helm 기반 앱을 쉽게 배포하고 관리하고 싶을 때
 - 통합 대시보드 + 관리도구 모음

## 주요 기능
| 기능 영역                       | 설명                                                   |
| --------------------------- | ---------------------------------------------------- |
| 🧭 **클러스터 관리**              | 여러 클러스터 생성/등록/삭제/버전 업그레이드까지 지원 (on-prem, EKS, GKE 등) |
| 👥 **RBAC + 사용자 관리**        | 여러 사용자/팀에 대한 권한 부여를 웹에서 쉽게 설정 가능                     |
| 🌐 **웹 UI 대시보드**            | kube-dashboard보다 훨씬 강력한 UI 제공 (리소스 모니터링, 배포 등)       |
| 🚀 **애플리케이션 배포 (Helm)**     | Helm chart를 웹에서 클릭 몇 번으로 배포                          |
| 📤 **CI/CD 연동**             | GitOps 기반 배포 가능 (예: ArgoCD, Flux 연동도 가능)             |
| 🔐 **보안 및 감사**              | CIS Benchmark 검사, 인증서 관리, 네임스페이스 격리 등                |
| 🌍 **멀티 클러스터 / 멀티 클라우드 지원** | EKS, AKS, GKE는 물론 자체 만든 클러스터까지 통합 관리                 |

## Dashboard vs rancher
| 항목         | Kubernetes Dashboard | Rancher             |
| ---------- | -------------------- | ------------------- |
| 설치 대상      | 단일 클러스터              | 여러 클러스터             |
| UI 기능      | 리소스 조회/편집 위주         | 관리, 인증, 모니터링, 배포 포함 |
| 배포 방식     | `kubectl apply`로 단순한 YAML 적용 | Helm chart 또는 Docker로 복잡한 앱 패키지 설치|
| 내부 구성     | 단일 pod + service 정도 | 여러 컨트롤러 + DB + UI + 인증 모듈 등 다수 컴포넌트 |
| Helm 지원    | ❌ 없음                 | ✅ 있음                |
| RBAC UI 관리 | ❌ (직접 설정 필요)         | ✅ 클릭 몇 번            |
| 실무 적합성     | 실습/학습용               | 기업용 운영환경에 적합        |
