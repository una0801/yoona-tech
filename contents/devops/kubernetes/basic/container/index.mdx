## 컨테이너란?
- 컨테이너는 애플리케이션과 그 실행 환경을 함께 패키징한 경량의 독립 실행 환경
- 호스트 OS 위에서 격리된 프로세스로 실행되며, 빠르게 시작되고 리소스 소모가 적음

  | 항목    | VM (가상 머신)         | 컨테이너                          |
  | ----- | ------------------ | ----------------------------- |
  | **OS 레벨** | 게스트 OS 필요          | 호스트 OS 공유                     |
  | **부팅 시간** | 수 분                | 수 초                           |
  | **무게감**   | 무거움                | 경량                            |
  | **실행 단위** | 하드웨어 수준            | 프로세스 수준                       |
  | **격리성**   | 완전                 | 프로세스 수준 (namespace + cgroups) |
  | **예시**    | VirtualBox, VMware | Docker, containerd            |

---
## 이미지와 레이어
- 컨테이너 이미지는 읽기 전용 레이어의 집합
  ```
  # 구조 예시
  Ubuntu Base Layer
  + Python 설치 레이어
  + pip 패키지 설치 레이어
  + 애플리케이션 코드 복사 레이어
  ---------------------------------
  = 최종 Docker 이미지

  ✅ docker history 이미지명 명령어로 이미지의 레이어 확인 가능
  ```
  - 각 dockerfile 명령어는 새로운 레이어를 생성
  - 이미지의 변경은 새로운 레이어로 추가됨 -> 캐시 효율성 증가
  - docke는 중복된 레이어를 공유해서 디스크 사용 최소화

## 네트워크
- 컨테이너는 **가상 네트워크 인터페이스**를 가지고 있으며 다음의 네트워크 모드 중 하나로 실행
  - **Bridge(기본값)**
    - docker가 자동으로 생성한 `docker0` 브릿지 네트워크 사용
    - 컨테이너들은 가상 브릿지에 연결되고 서로 통신 가능
    - 외부에서 접근하려면 포트포워딩 필요
      ```bash
      # (ex)
      docker run -p 8080:80 nginx
      ```
  - **Host**
    - 컨테이너가 호스트의 네트워크 인터페이스를 그대로 사용
    - 퍼포먼스는 좋지만 네임스페이스 격리는 없음
  - **None**
    - 네트워크 인터페이스 없음 (완전격리)

## 볼륨(저장소)
- 컨테이너는 기본적으로 **휘발성 파일 시스템** 사용
- 컨테이너가 삭제되면 내부 데이터도 사라짐
- 볼륨 사용 목적
  - 데이터 유지(Persistence)
  - 호스트와 파일 공유
  - 여러 컨테이너 간 공유
- Docker 에서의 볼륨 타입
  | 타입         | 설명                                             |
  | ---------- | ---------------------------------------------- |
  | Volume     | Docker가 관리하는 디렉토리 (`/var/lib/docker/volumes/`) |
  | Bind Mount | 호스트의 특정 디렉토리를 직접 마운트                           |
  | tmpfs      | 휘발성 메모리 볼륨 (리눅스 전용)                            |

- 사용예시
  ```bash
  docker run -v myvolume:/data redis
  ```
